# Expired idle Culqi holds in administration

Audited from PR11 `d1d539670d720df5f467e8c4f31a17d345bce3a4`. No hosted database, payment API or real administrative session is used by this audit. The branch `fix/admin-culqi-proof-label-20261016` disables its own automatic Vercel deployment before publication.

An idle hold can intentionally remain `payment_pending_review` / `pending` after `payment_expires_at`. The client expiry handler closes the SDK and disables retry without writing payment state. Capacity reads exclude expired Culqi pending/failed holds through `consumesBatchCapacity`. Only an explicit, authenticated checkout status request invokes `expire_culqi_token_session`; that transaction can persist `expired/cancelled` for a safe idle hold or preserve an unresolved charge for review. Reading administration does not invoke that transition.

Administration retains the actual persisted state: `Not confirmed`, `Culqi · pending` and the pending-attention filter. Its status-based pending counts and financial pending value still include this record; they describe unconfirmed persisted orders, not available capacity. The batch capacity panel excludes the elapsed hold. Confirmed revenue, production and delivery exclude the unpaid record. Rendering the list neither cancels nor renews the hold. No background cancellation or new operational policy is introduced here.

The concrete presentation defect was the unconditional proof caption `webhook verified` for every Culqi order. An elapsed idle hold with no charge or event also received that claim. The caption now reads `No voucher required · managed by Culqi`, which identifies the provider without asserting an observed webhook or paid result. Payment badges and all data, capacity, financial and settlement logic remain unchanged.

`tests/operator-flow-http.mjs` renders the compiled authenticated admin page against a disposable PostgreSQL 17 container with no network and a loopback-only PostgREST fixture. The expired synthetic row stays pending/idle, consumes zero batch capacity, contributes zero confirmed revenue/production and retains S/58 in pending financial value. The test checks the real rendered badges/caption, snapshots all rows before/after the GET and checks zero transport writes. It fails against the original caption before the one-line fix and passes after rebuilding. Existing SQL expiry regressions verify that explicit expiry is transactional, idempotent and preserves unresolved charges.
